# Web 视觉检查清单

本清单约束测试计划的视觉断言，以及执行/完成时的视觉判读；不新增 evidence schema。
页面结构、DOM 文本、元素存在或“截图已保存”均不能单独证明显示正常。

## 按风险选择范围

- `none`：无实质可见变化，记录理由，不展开清单。
- `browser-smoke`：真实操作后查看当前截图或等价视觉 artifact，检查受影响区域的显示完整性、明显遮挡及布局异常，
  记录所见与结论；不要求无关区域扫描、全尺寸矩阵或完整 geometry 测量。
- `browser-layout`：涉及布局、显示不全、溢出、遮挡、响应式风险时，必须覆盖下表适用项目，
  并保留 viewport、相关元素 geometry、overflow 与交互前后证据。发现新布局风险应补充场景与证据，不继续以 smoke 判通过。

## 可执行断言

按受影响区域和实际风险选择场景，不机械生成所有尺寸、所有状态的笛卡尔积。
`browser-layout` 对下列类别标记 `applicable` 或 `not_applicable` 并说明理由；只展开适用项目。

| 检查类别 | Then 必须描述的可观察结果 | 数据/动作示例与证据 |
|---|---|---|
| 显示完整性 | 标题、正文、输入框、按钮和弹窗内容无非预期裁切/显示不全；有意省略的内容按产品约定可查看，关键操作可达 | 长文本、长名称或校验信息；查看截图，检查边界与实际展开/滚动结果 |
| 溢出与滚动 | 页面/容器无非预期横向溢出；预期滚动区域能到达末项与底部操作；内容不撑破容器 | 大量数据、长连续字符串；相关容器 client/scroll 尺寸、边界和真实滚动前后截图 |
| 遮挡与层级 | 控件不意外重叠，浮层/固定栏不遮住当前内容和关键操作；模态遮罩等预期遮挡不误报 | 打开下拉框、弹窗或抽屉；截图、元素边界/层级观察与真实点击验证 |
| 布局稳定性 | 对齐、间距、换行和区域排列符合已确认原型/现有布局约束，无挤压、错位或布局混乱 | 受影响区域截图与适用的元素位置/尺寸；有基线时对比基线，不凭主观审美制造缺陷 |
| 视口与状态变化 | 在约定的目标视口，以及受影响的加载/空态/错误态/展开关闭状态下，仍满足上述不变量 | 写明实际宽高、数据和状态转换；截图及交互前后 geometry，不虚构移动端支持 |

正常滚动、设计允许的省略和有意覆盖不等于缺陷；断言应区分预期行为与非预期异常。
仅 `scrollWidth <= clientWidth` 不能证明没有裁切/遮挡，单张截图也不能证明交互或所有状态正确。

## 场景和证据写法

每个适用检查映射到稳定 scenario id，可合并进已有行为场景：

- Given：目标区域/Surface ID（已有时）、具体 viewport、数据边界、初始状态及配置 Provider。
- When：真实进入、输入、展开、滚动或切换状态；不是注入最终 DOM 或仅保存截图。
- Then：具体哪段内容完整、哪个容器不溢出、哪个按钮不被遮挡且可操作、哪项布局不变量成立。
- Evidence：截图路径/hash、区域和状态、实际视觉判读结论；layout 再附 viewport、geometry、overflow、before/after。
  执行结果写入现有 `visible_result` 或其引用的证据报告，不新增必填机器字段。

测试计划中写预期证据，不提前填写“通过”。执行者必须实际查看视觉 artifact，逐项记录观察到的结果及异常；
只有截图文件存在但未查看/未给出判断时，该视觉检查仍为 `incomplete`。实际缺陷记为 `failed`，缺证据记为
`incomplete`，Provider/环境不可用记为 `blocked`/`incomplete`；均不得声明通过。
